# usage-meter：交接說明

這是一個 Claude Code 的 mod，它在輸入框上方常駐顯示一行用量資訊。

## 本週總計移到「本週各資料夾」標題後面

## 0.16.0：使用時間下方加「本週各資料夾」

## 2026-11-17：月曆用本機紀錄補算過一次（一次性，不在程式裡）
- 使用者選擇「用本機紀錄估算補上」。讀這台電腦的對話紀錄（`Claude-Tcan/claude-config/projects` 和 `~/.claude/projects`，128 個對話、5,532 則回覆），把每則回覆的 token 依粗略成本加權（輸出 ×5、快取寫 ×1.25、快取讀 ×0.1），再按每天的比例分配當時 7 天已用的 48%。結果直接寫進 mod 的 `$.store`（`plugins/store/usage-meter_inline-*.json` 的 `week-use-v1.days`）。
- 補算結果：11/12 18.1%、11/16 14.8%、11/17 7.1%、11/13 6.3%，其他天 ≤1.1%。
- 這是**估算**：claude.ai 網頁版或其他電腦的用量讀不到；各模型的實際扣額方式也不是這個權重。之後的日子都是 mod 自己記錄的實際增加量。

## 0.15.0：月曆放大、字與灰色統一
- 月曆放大：方格 16px、間距 4px、圓角 3.5px、月份字 12px；SVG 固定寬高並**靠左**（使用者說原本置中）。
- 「5 小時」「7 天」「每天用掉的 7 天額度」用同一個 `label()`（同一種字）。
- 灰色統一：桌面版、手機、VS Code 的額度增溫條「還沒用到」的格子、使用時間的 0 格子，都用跟月曆空格一樣的半透明灰 `SVG_EMPTY`。終端機畫不了半透明，仍用主題的 `subtle`。
- 已知：月曆只記錄**這版載入之後**、7 天額度**增加**的部分。第一次載入時的已用 % 只當起點，所以當天稍早的用量不會出現（使用者在 18:1x 載入時已用 47%，今天格子因此是灰的）。是否用本機對話紀錄補算，使用者還沒決定（本機只有今天的紀錄，補算會把 47% 全算在今天）。

## 0.14.0：月曆改成 SVG 正方形圓角
- 使用者要**正方形、有一點圓角**、格子之間要有空白。Box 在桌面版的一格是長方形（又高又窄），而且沒有圓角，所以桌面版、手機、VS Code 改用 `Svg` 元素畫整張月曆（`calendarSvg`）：方格 12px、間距 3px、圓角 2.5px，上面一列寫「9月」「10月」。
- `isInteractive`：滑鼠移到格子上，`<title>` 會顯示「11/17：用掉 25%」。
- SVG 裡不能用 app 的主題色：沒用量的格子和月份文字用半透明灰 `rgba(138,143,152,…)`，深色、淺色模式都看得到。
- **終端機**畫不出 Svg（它的元素表裡雖然有 `Svg`，但畫出來是空的），所以用 `e.surface !== 'terminal'` 判斷，終端機沿用 Box 方塊（寬 2、高 1、`gap="xs"`）。
- 測試：桌面版檢查 SVG 的格子都是正方形、有圓角，顏色和位置也對；終端機檢查方塊的版本。

## 0.13.0：月曆小方格（每天用掉多少 7 天額度）
- 使用者參考 GitHub／DOTA2 那種年曆格子：**每一欄是一週，由上到下是週一到週日**，最右邊是這週，還沒到的日子不畫。
- 放在額度段落最下面，標題「每天用掉的 7 天額度」，上面一列是月份數字（換月的那一欄才寫）。週數依寬度算：`(bodyColumns − 2) / 3`，限制在 4–16 週。
- 顏色（使用者指定，TCAN logo 三色）：0 灰、**≤10% 淺藍 `#0DCAFE`、10–20% 深藍 `#1A67F8`、>20% 紅 `#FF5561`**（`useColor`）。
- 怎麼算一天用了多少：每次 `session.measure` 帶來新的 `seven_day` 已用 %，跟 `$.store` 裡上一次的數字比，**增加**的部分算進今天；減少（舊用量滾出 7 天視窗、或重置）不算，只更新基準。
  - 存在 `$.store` 的 `week-use-v1`：`{ last, days: { 'YYYY-MM-DD': % } }`，保留 120 天，所有對話共用。`last` 也共用，所以同一段增加不會被不同對話重複算。
  - 每分鐘重新讀一次，別的對話記到的也會出現。
- **從裝上這版開始才有資料**，之前的日子都是灰色。
- 測試：增加才算（30→34→40→25→隔天 28 ⇒ 11/17 記 10、11/18 記 3）、格子位置與顏色。

## 需求（使用者最新的說法）
> 我其實只是想知道 5 小時剩多少，7 天剩多少，分別什麼時候重置

0.1.0 和 0.2.0 顯示了 token、上下文、花費、進度條和按鈕。使用者覺得**太複雜**，所以 0.3.0 只保留這兩個額度。之後要改進的話，請維持簡單，不要再加回這些東西。

## 0.4.0 顯示什麼
0.3.0 是輸入框上方的一行文字，使用者覺得醜。0.4.0 改成桌面 app 的**小工具（widget）**，標題「用量」，每個額度三行：
```
5小時                剩 72%
[████████████████░░░░░░]   ← Box 畫的彩色條：>30% 綠、≤30% 黃、≤10% 紅
今天 18:00 重置
```
重置時間會寫成「今天」、「明天」或「11/21（五）」。還沒有資料時，顯示「下一次回覆後顯示額度」。
**不會自動打開**。輸入框上方有一顆小按鈕「📊 用量」，點一下打開小工具，按鈕變成「收起用量」，再點一下關掉。用小工具自己的 × 關掉時，`ui.close` hook 會把按鈕改回來。也可以輸入 `/usage-meter` 打開。

## 0.9.0：兩顆按鈕各自開關，同一個小工具上下排（取代 0.8.0 的做法）
- 使用者要的行為：
  - 「◷ 1h23m」和「▮▮▯ 用量」**各自開關**，打開後各自變成「◷ 收起」和「▮▮▯ 收起」。
  - 兩個都開：同一個小工具，上面額度、下面使用時間，標題「用量與時間」。
  - 只開一個：只顯示那一段，標題「用量」或「使用時間」。

- 狀態：`showUsage`、`showTime`（usage-meter 自己的）。`syncPane` 依兩個開關開、改標題或關小工具（對同一個 id 再 `ui.open` 會改標題）。
- **時間資料直接讀 usage-time 的 `$.state`**（`usage-time.workMs`、`usage-time.days`），只讀不寫。contract 裡也宣告了這兩個 key，型別要跟 usage-time 一致。驗證器會標成「其他 mod 的狀態，不檢查」。
- 0.8.0 的 `/usage-time data` 指令**已拿掉**：外掛呼叫指令會在對話裡留下 `usage-time: {...}` 一串字，使用者看到了。**不要再用指令傳資料。**
- 測試 5 個：單獨、兩顆各自開關（標題順序：使用時間 → 用量與時間 → 用量）、上下兩段、只開時間、單獨時不顯示時間。

## 0.8.0：額度與使用時間在同一個小工具（已被 0.9.0 取代）
- 使用者要「用量跟使用時間在同一個畫面的上面跟下面」。兩個都裝時，usage-meter 的小工具標題變成「用量與時間」：上半部是額度，下半部是使用時間（四個數字＋本週每天長條）。兩顆按鈕都開關這同一個小工具。
- 資料怎麼傳：usage-time 回應 `/usage-time data`，回傳 JSON（`TimeData`：`startedAt`、`workMs`、`days`）。usage-meter 在 `session.start`、每分鐘迴圈、主對話 `turn.complete`、按按鈕時呼叫 `refreshTime`，存進 `timeData` atom，**畫面只讀這個 atom**。
- 引擎規則（踩過的雷）：
  - `ui.render` 裡不能寫 state（會被拒絕、整個 hook 被跳過），也不該呼叫指令。
  - `command.run` hook 裡不能再呼叫 `$.command.run`。所以兩個都裝時，`/usage-time` 只回一句提示，請使用者用按鈕或 `/usage-meter`。
- 下半部的畫法是從 usage-time 複製過來的，改樣式時兩邊要一起改。

## 運作方式（`hooks/register.tsx`）
- `session.start`：呼叫 `$.session.usage()` 取出 `rateLimits`，註冊 `/usage-meter` 指令，然後 `$.ui.open({ placement: 'widget' })`。
- `session.measure`：引擎每個 turn 結束後、或額度移動一整個百分點時推送 `rateLimits`，存進 `$.state` 的 `usage-meter.limits`。
- `ui.render`，比對 `{ component: 'Pane', requestId: 'usage-meter' }`：畫小工具。進度條是兩個 `flexGrow` 分別為「剩餘」與「已用」的 Box，顏色用主題色 `success` / `warning` / `error`，底色用 `subtle`。
- `placement: 'widget'` 只是請求，由 app 決定。終端機或 VS Code 會改成一般的 pane。
- 只保留 `kind` 為 `five_hour` 和 `seven_day` 的視窗。`percentUsed` 是已用的百分比，剩餘 = 100 − 已用。`resetsAt` 是 ISO 時間。
- 只有訂閱方案才有這些資料，而且要等第一次 API 回覆之後才有。
